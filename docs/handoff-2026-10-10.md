## What happened this session

**`3bdb859` — locale: read device locale without the framework binding**
Fixed two `layout_migration_test` failures introduced by `8fe1368`:
`_loadSettings()` read `WidgetsBinding.instance.platformDispatcher`, which
throws in plain `flutter_test` runs (no `TestWidgetsFlutterBinding`), so the
catch-all reset every setting and persisted `layout_mode` /
`font_size_multiplier` silently never loaded. Reads `dart:ui`
`PlatformDispatcher.instance` now — same dispatcher in a real app, works
before the binding exists.

**`41ac766` — video: port jidoujisho player, youtube source and
customization**
The user scoped the jidoujisho port to "only video player and
youtube/local media feature with subtitles and customization".
- `lib/core/services/youtube_service.dart` (new): URL→ID, muxed stream
  list, closed-caption tracks and cues. The stream manifest skips the watch
  page (`requireWatchPage: false`) — YouTube rate-limits watch-page hits
  far more aggressively than the innertube API. Metadata degrades to the
  video ID when the watch page is blocked; playback never depends on it.
- `video_tab.dart`: YouTube URL dialog → best muxed stream through
  `video_player`; caption tracks → language picker → cues for the
  transcript and overlay. Muxed only — video-only quality needs separate
  audio muxing that `video_player` does not offer.
- Customization persisted in AppState: `video_playback_speed` (0.25–2.0),
  `video_subtitle_scale` (0.5–2.5), `video_subtitle_offset_ms`
  (±30000, positive shifts subs later). Seeking compensates the delay.
- `fvp` (0.39.0) registers a desktop `video_player` backend on
  Linux/Windows: `video_player` ships no desktop implementation, so local
  playback was a silent no-op on Linux before this.
- `youtube_explode_dart` 3.1.0 (pure Dart). `media_kit` was tried first and
  abandoned: `media_kit >=1.1.0` needs `image ^4`, but `epubx` (reader +
  `epub_view`) uses `decodeImage()`, removed in image 4 — version solving
  fails. Do not re-attempt media_kit without replacing epubx.

**`e9f310d` — test: gate ichi.moe checks, time out requests at 10s**
`ichi_moe_service_test.dart` hit the live network unconditionally and
flaked under full-suite load (same class as the wiktionary flake fixed in
`68e3cf1`): the service's `http.get` had no timeout, so a hung request
blocked past the per-test timeout. Now gated behind
`--dart-define=ICHI_MOE_LIVE=true`, requests time out at 10s like mdbg,
and the tests' dead try/catch is gone (search swallows every error and
returns an empty list).
